# WebVideoHarbor 联盟推荐设计

日期：2026-07-28  
状态：已确认

## 背景

WebVideoHarbor v1.0.0 Community Edition 是完全免费、开源、本地运行的网页媒体技术项目。项目不设置付费墙，也不销售远程安装或排障服务。本次变更尝试通过少量、透明的联盟推荐支持项目维护，同时保持扩展核心体验、隐私承诺和开源定位不变。

## 目标

- 建立一个由 GitHub Pages 托管的静态推荐资源页。
- 在扩展设置页提供低干扰、用户主动点击的推荐页入口。
- 第一版只展示两个与项目使用场景有关的推广入口：移动固态硬盘和阿里云产品。
- 明确披露推广关系，不增加广告 SDK、行为分析、点击统计或远程配置。
- 确保推荐功能失效时不影响视频识别、下载和本地助手。

## 非目标

- 不在用户访问的第三方网页中注入广告或推广链接。
- 不在扩展弹窗、系统通知或下载流程中强制展示广告。
- 不要求用户点击广告后才能使用功能。
- 不根据访问网址、媒体地址或下载记录进行广告定向。
- 不引入 NAS 推荐、动态商品列表、后台管理系统或广告竞价网络。
- 不展示未经核实的实时价格、折扣、容量、品牌或性能承诺。

## 已选方案

采用“GitHub Pages 推荐页 + 扩展设置入口”的组合。

推荐页由仓库中的静态 HTML 和 CSS 构成，通过 GitHub Pages 发布。扩展设置页只包含固定的推荐页地址，不直接包含联盟参数，也不加载第三方脚本。用户只有主动点击设置页入口、进入推荐页并再次点击某个推广按钮后，才会访问商家页面。

访问流程：

```text
扩展设置页
  -> GitHub Pages 推荐资源页
    -> 用户主动点击推广卡片
      -> 淘宝或阿里云页面
```

## 页面与文件结构

计划在现有 `docs/` 目录中增加 GitHub Pages 所需的静态页面和样式。最终文件名以实施计划为准，页面至少包括：

- 项目首页：介绍 WebVideoHarbor，并提供安装说明、隐私说明、使用边界和推荐资源入口。
- 推荐资源页：包含统一披露和两张推广卡片。
- 共享样式：延续扩展现有的蓝灰色、低干扰视觉风格，支持桌面和手机尺寸。

GitHub Pages 预计公开地址：

```text
https://phpfrank.github.io/web-video-harbor/
```

扩展设置页在“隐私与安全”区域之后增加一个独立卡片。文案为：

> 可选推荐  
> 查看适合保存和管理视频的存储与云服务。页面可能包含推广链接。

入口不会出现在下载按钮、任务列表或错误提示中。

## 推荐内容

第一版仅包含以下两个入口。

### 移动固态硬盘选购入口

- 推广地址：`https://s.click.taobao.com/KXMdz3k`
- 用途说明：适合保存体积较大的本地视频文件。
- 限制说明：具体品牌、型号、容量、价格和售后以商家页面实时信息为准。
- 不在页面展示用户提供的 `1082.05 元`，因为价格可能变化，且当前推广文案没有给出可核实的品牌、型号和容量。

### 阿里云产品与对象存储

- 推广地址：`https://www.aliyun.com/minisite/goods?userCode=c5z9bjlt`
- 用途说明：适合需要了解对象存储、云端保存或其他云产品的用户。
- 限制说明：适用范围、费用和返利资格以阿里云页面实时信息为准。

两个入口均使用普通文本和 CSS 图形，不复制未经授权的商家 Logo、宣传图或商品主图。

## 披露与链接规则

推荐资源页顶部固定显示：

> 本页包含推广链接。如果你通过这些链接购买产品，项目维护者可能获得佣金，但不会增加你的购买价格。推荐内容不会影响 WebVideoHarbor 的功能。

每张卡片必须：

- 显示清晰的“推广”标识。
- 使用用途说明而不是夸张营销文案。
- 将跳转按钮标记为外部链接。
- 使用 `target="_blank"` 和 `rel="sponsored noopener noreferrer"`。
- 不声称“最低价”“最安全”“永久可靠”或类似无法核实的结论。

README、扩展设置页和推荐页都需要披露推荐页可能包含推广链接。如果项目以后提交 Chrome Web Store，商店介绍和安装前披露也必须同步说明联盟推广。

## 隐私与数据处理

扩展继续保持本地运行，不增加遥测、广告 SDK 或用户行为跟踪。扩展不会把当前网址、媒体地址、下载记录、配对密钥或其他用户数据传给推荐页或商家。

`PRIVACY.md` 需要把当前绝对表述“项目不包含广告”调整为更准确的边界：

- Chrome 扩展和本地助手不包含广告 SDK、遥测或个性化广告。
- 项目官网可能展示清晰标注的联盟推荐链接。
- 只有用户主动点击外部链接后，目标商家才会按照其自身条款处理访问。
- WebVideoHarbor 不增加自己的点击跟踪或中转服务。

## 错误与失效处理

- GitHub Pages 无法访问时，扩展只打开普通浏览器错误页，下载功能不受影响。
- 推广链接失效时不做自动替换、静默重定向或远程下发。
- 发布新版本前人工检查两个推广链接；发现失效后通过代码更新或暂时移除相应卡片。
- 推荐页不读取远程 JSON，也不根据用户环境动态更换链接。

## 验证范围

实施需要覆盖以下验证：

- 静态页面在桌面和手机宽度下布局正常。
- 两张卡片均存在“推广”标识、用途说明和限制说明。
- 两个外链均包含 `rel="sponsored noopener noreferrer"`。
- 扩展设置页只能打开固定的 GitHub Pages 推荐页地址。
- 推荐入口不传递当前标签页、媒体或下载数据。
- 原有密钥保存、助手连接、平台兼容和下载功能测试继续通过。
- README、隐私说明、扩展披露和网页披露保持一致。
- GitHub Pages 发布后验证公开地址和两个推广地址可以访问。

## 发布边界

设计文档和实施计划可以先提交。正式页面、扩展入口和披露更新需要作为一个完整变更一起发布，避免出现只有推广入口但没有隐私披露，或只有页面但扩展指向尚未启用地址的状态。
