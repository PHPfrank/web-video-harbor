# WebVideoHarbor 商业化设计

> **状态：已废弃。** 本商业化方案已由 [2026-07-28 WebVideoHarbor 社区开源版设计](2026-07-28-webvideoharbor-community-open-source-design.md) 取代，仅作为历史决策记录保留，不是当前产品方向。

日期：2026-07-27

目标版本：v0.3.0 商业验证版

## 1. 目标

WebVideoHarbor 采用低投入、低风险的副业模式验证付费需求。产品继续强调本地处理、隐私优先、无广告，不上传用户的视频、网页地址、Cookie 或账号信息。

首期不建设支付网站、用户账号系统或在线授权服务器。目标是在 30 天内验证：普通用户是否愿意为复杂视频处理、安装服务和及时答疑付费。

## 2. 产品定位与边界

产品对外定位为“本地隐私优先的网页视频保存与素材整理助手”，不宣传为绕过平台限制的万能下载器。

所有版本均遵守以下边界：

- 只处理用户有权保存的内容。
- 不绕过登录、会员、付费墙、地区限制、加密或 DRM。
- 不读取或导出浏览器 Cookie、登录凭证和账号信息。
- 不承诺所有网站或所有视频都能下载。
- 平台规则变化、网络限制和访问控制导致的失败，应给出清楚提示，不伪装成普通程序故障。

## 3. 版本划分

### 免费基础版

免费版只让客户体验简单 HTML 视频下载：

- 识别网页直接暴露的 HTTP/HTTPS MP4。
- 下载一个普通 MP4 文件。
- 显示下载进度。
- 支持取消、重试和在 Finder 中定位文件。
- 不支持 `blob:`、M3U8、平台页面、加密或需要登录的资源。

免费版识别到 M3U8、YouTube、Bilibili 等复杂候选时，可以显示候选名称、Pro 标识和升级说明，但不得提交受限下载任务。

### Pro 永久版

Pro 包含免费版全部功能，并解锁：

- 非加密、非 DRM 的 M3U8/HLS 分片下载与合并。
- 多清晰度 M3U8 选择。
- YouTube 无需登录即可观看的公开单视频。
- Bilibili 无需登录即可观看的公开单视频。
- 微信视频号普通 MP4 或非加密 M3U8 的最佳努力识别。
- 720P、1080P 和最佳画质选择，实际结果取决于源站。
- DASH/M4S 等音视频分离资源的自动合并。
- 后续规划的批量任务、字幕、封面、音频提取和格式转换。
- 工作时间优先答疑。

“永久版”表示用户可以永久使用已经购买并激活的 Pro 版本，并获得当前大版本内的兼容性和维护更新。未来完全重做的大版本可以另行制定优惠升级政策。

### 远程安装服务

远程安装是人工服务，不等同于软件授权：

- 帮助安装 Chrome 扩展和本地助手。
- 配置配对密钥、下载目录和必要依赖。
- 使用一个合规测试页面完成现场验证。
- 处理本次安装产生的问题。
- 不承诺解决平台访问限制或让任意网页可下载。

## 5. 授权方案

### 用户流程

1. 用户安装免费版并体验普通 MP4 下载。
2. 用户购买 Pro 后，在软件中复制设备申请码。
3. 用户把申请码发送给销售者。
4. 销售者在自己的 Mac 上运行私有签发工具，生成设备专用激活码。
5. 用户输入激活码，软件显示“Pro 永久版已激活”。
6. 激活后可以离线使用，不依赖授权服务器。

### 授权规则

- 一个订单供购买者本人最多两台 Mac 使用。
- 每台 Mac 使用单独的设备申请码和激活码。
- 用户更换电脑时可以联系销售者人工重置。
- 首期由销售者保存最小化订单记录和已签发设备数量，不建设线上账户系统。

### 技术方案

- 使用非对称数字签名生成许可证，建议采用 Ed25519。
- 私钥只保存在销售者电脑上的私有签发工具中，绝不进入 GitHub、安装包、日志或测试夹具。
- 应用只内置公钥，用于离线验证许可证签名。
- 设备申请码使用本地设备标识的不可逆摘要，不向客户展示原始硬件序列号。
- 许可证至少包含格式版本、产品、设备码、授权级别和签发编号。
- Pro 权限由本地助手验证，扩展只展示助手返回的授权状态。
- Pro API 必须在助手端再次检查授权，不能只依赖扩展按钮是否隐藏。
- 私有签发工具生成新密钥时必须明确警告：丢失私钥会导致以后无法为原有产品签发兼容许可证。

授权的目标是防止普通用户随意共享，不追求无法破解。不得为反破解收集侵入性设备信息或要求持续联网。

## 6. 软件与代码分发

采用“免费核心公开、Pro 专属代码私有”的 open-core 方式：

- 现有公开的 v0.2.1 历史和 Release 保持不变，不删除、不篡改。
- GitHub 公共仓库从商业版开始保留免费版源码、文档、问题反馈和免费安装包。
- Pro 专属实现、许可证签发工具和私钥材料放在私有仓库或本机私有目录。
- 私钥、真实许可证和客户设备码永远不得提交到任何仓库。
- 免费版和 Pro 版使用明确的产品标识，避免客户误装后无法判断版本。
- 首期可以分别提供免费安装包和 Pro 安装包；购买者收到 Pro 安装包和激活码。

公开仓库需要补充适合 open-core 模式的许可证说明。在许可证确定前，不对外宣称“开源软件”，只描述为“公开提供免费版源码”。第三方依赖的许可证、署名和再分发条件必须单独审查。

## 7. 交互与数据流

### 免费下载

Chrome 扩展识别普通 MP4 → 提交给本地助手 → 助手验证 URL 和配对密钥 → 下载到受控目录 → 返回进度和结果。

### Pro 候选

Chrome 扩展识别 M3U8 或受支持平台页面 → 查询助手授权状态 → 未激活时显示 Pro 说明 → 已激活时提交任务 → 助手再次验证许可证 → 调用对应下载与合并流程。

### 激活

助手生成设备申请码 → 用户线下发送申请码 → 私有签发工具生成签名许可证 → 用户输入许可证 → 助手验证签名和设备绑定 → 本地安全保存 → 扩展刷新授权状态。

## 8. 错误处理

必须区分以下情况：

- `pro_required`：识别到了 Pro 类型视频，提示升级，不显示为下载故障。
- `license_invalid`：激活码格式或签名无效，提示核对完整内容。
- `license_device_mismatch`：激活码不属于本机，提示联系支持。
- `license_unsupported`：许可证版本过新或产品不匹配，提示升级应用。
- 平台验证、网络过滤、解析器过期、DRM 和登录限制继续使用各自明确提示。

日志不得记录完整激活码、私钥、原始设备标识、Cookie、配对密钥或完整签名媒体地址。

## 9. 销售与服务流程

1. 用户通过 GitHub 或内容渠道获得免费版。
2. 免费版完成普通 MP4 体验，并在复杂候选处展示 Pro 能力和联系方式。
3. 用户选择 Pro、远程安装或组合套餐。
4. 收款后，用户发送设备申请码。
5. 销售者签发激活码，并记录订单、签发数量和支持状态。
6. 工作时间优先回复 Pro 用户；用 FAQ、诊断信息和标准话术控制人工成本。

对外说明必须写明支持范围和不支持范围。不能使用“支持所有网站”“保证下载成功”或“绕过平台限制”等表述。

## 10. 30 天验证计划

首轮验证目标：

- 20 名用户实际安装免费版。
- 5 名用户购买 Pro 或远程安装服务。
- 记录客户最常使用的网站、失败类型和购买原因。
- 单个客户平均人工支持时间控制在 30 分钟以内。
- 暂不投入在线支付、授权服务器和大额广告。

验证结束后，根据真实数据决定优先开发批量下载、字幕封面、格式转换或自动更新，而不是同时开发所有功能。

## 11. 测试与验收

商业版发布前至少验证：

- 未激活状态只能创建普通 MP4 任务。
- 未激活状态对 M3U8 和平台任务返回 `pro_required`。
- 修改扩展前端不能绕过助手端授权检查。
- 正确许可证可以在绑定设备离线激活并持续生效。
- 错误签名、错误设备、损坏内容和不支持版本均被拒绝。
- 日志和 API 响应不泄露许可证、设备原始信息或密钥材料。
- 免费版原有 MP4 下载、取消、重试和 Finder 定位没有回归。
- Pro 版现有 MP4、M3U8、YouTube 和 Bilibili 流程通过自动测试和合规的现场测试。
- 免费安装包和 Pro 安装包具有清晰的名称、版本和校验值。

## 12. 暂不实施

- 在线支付网站。
- 用户注册和账号中心。
- 在线授权服务器或持续联网校验。
- 订阅收费和下载次数套餐。
- Windows 版本。
- 绕过登录、付费、地区限制、加密或 DRM。
