# WebVideoHarbor v0.2.0 平台视频下载设计

日期：2026-07-24

## 目标

在保留 v0.1.0 普通 MP4 与非加密 M3U8/HLS 下载能力的基础上，为 macOS 版增加 YouTube 和哔哩哔哩公开视频下载。v0.2.0 处理平台常见的 DASH/M4S、音视频分离和自动合并，继续提供进度、取消、重试与 Finder 定位。

## 已确认的产品范围

- 支持无需登录即可观看的 YouTube 与哔哩哔哩公开视频。
- YouTube 首版支持普通视频、Shorts 与 `youtu.be` 单视频短链接。
- 哔哩哔哩首版支持普通 `BV`/`av` 单视频页面。
- 一次只下载当前页面的一个视频，不下载播放列表、频道、合集或整季内容。
- 不读取或导出 Chrome Cookie、账号、浏览历史或登录信息。
- 不处理会员、付费、私有、地区限制、DRM 或必须登录的内容。
- 用户可选最佳画质、1080P 或 720P。目标画质不存在时，自动选择不高于目标的最佳可用画质。
- 下载后优先无损封装为 MP4；无法安全封装为 MP4 时允许输出 MKV。
- macOS 安装包内置固定版本的 `yt-dlp`，用户不需要另行安装解析器。
- `yt-dlp` 不静默自更新；平台兼容更新通过 WebVideoHarbor 新版本发布。

## 方案选择

采用“扩展提交页面地址，本地助手调用内置 `yt-dlp`，FFmpeg 合并”的方案。

未采用的方案：

- 自行实现 YouTube 与哔哩哔哩解析器：安装包可更小，但平台规则变化频繁，开发与维护成本过高。
- 在线解析服务：便于集中更新，但会暴露用户访问记录，引入服务器成本与额外故障点，不符合本地隐私定位。

`yt-dlp` 提供 macOS 通用独立可执行文件，支持格式选择、音视频下载与 FFmpeg 合并；其支持列表包含 YouTube 和哔哩哔哩。不过平台可能随时改变规则，因此“列入支持列表”不等于永久保证可用。

参考：

- <https://github.com/yt-dlp/yt-dlp/blob/master/README.md>
- <https://github.com/yt-dlp/yt-dlp/blob/master/supportedsites.md>

## 总体架构

### Chrome 扩展

扩展保留现有 MP4/M3U8 媒体发现流程，并新增受支持平台页面识别：

1. 获取当前标签页 URL 和标题。
2. 若 URL 是受支持的 YouTube 或哔哩哔哩单视频页面，生成一个“平台视频”候选。
3. 弹窗为该候选提供最佳画质、1080P、720P 三个选择。
4. 用户点击下载后，向本地助手提交平台页面 URL、标题、来源类型与画质枚举。
5. 非平台页面继续使用 v0.1.0 的媒体扫描结果。

扩展不解析平台签名、不收集 Cookie，也不向外部服务发送页面地址。

### 本地助手 API

任务请求在现有直连媒体任务之外新增平台任务类型。服务端不信任扩展传入的来源类型，而是根据标准化 URL 重新识别平台。

平台任务只接受固定画质枚举：

- `best`
- `1080`
- `720`

助手健康状态增加解析器可用性和版本字段，但不得返回命令路径、配对密钥或其他本机敏感信息。

### 平台 URL 校验

平台入口只接受 HTTPS，并对规范化后的主机与路径做精确匹配。拒绝：

- 相似或后缀欺骗域名；
- URL 用户名/密码；
- 非标准端口；
- 播放列表、频道、搜索、收藏、合集或直播入口；
- 不支持的平台；
- 不能可靠归类为单视频页面的 URL。

短链接允许交给 `yt-dlp` 解析，但任务仍强制单视频模式。

### yt-dlp 运行器

Go 助手新增独立运行器组件。运行器使用参数数组直接启动固定路径中的内置可执行文件，不经过 Shell，也不接受用户自定义参数。

固定约束包括：

- 禁用配置文件读取，避免用户或系统级 `yt-dlp` 配置改变安全边界；
- 不读取浏览器 Cookie；
- 强制单视频，不展开播放列表；
- 为三个画质档位使用预定义格式选择器；
- 使用现有 FFmpeg 路径进行合并；
- 输出模板固定在助手创建的任务临时目录；
- 最终文件只能由助手安全发布到下载目录；
- stdout/stderr 只解析受控进度与结果标记，不把原始完整输出直接写入日志或返回前端。

运行器负责把下载百分比、已传输字节和阶段信息转换为现有任务进度模型。合并阶段显示“正在合并音视频”，不伪造百分比。

### 输出与清理

每个任务使用下载目录内受控的临时工作区。`yt-dlp` 不直接决定最终公开文件路径。助手验证输出是普通文件、位于任务目录内且扩展名允许后，再使用现有发布逻辑生成安全文件名并原子发布。

失败或取消时删除 `.part`、临时音频、临时视频和任务工作区。已完成文件不覆盖，沿用自动增加序号的规则。

### 取消与重试

取消平台任务时，助手终止 `yt-dlp` 及其启动的 FFmpeg 子进程，并等待清理完成后才把任务标记为已取消。重试创建新的受控运行过程，不复用可能损坏的分片。

## 用户界面

受支持的平台页面即使没有暴露普通媒体 URL，扩展也显示一张“平台视频”卡片。卡片包含：

- 页面标题；
- 平台名称；
- 画质选择：最佳画质、1080P、720P；
- 下载按钮；
- “仅支持无需登录即可观看的公开视频”提示。

现有 MP4/M3U8 卡片、任务列表和设置页保持兼容。健康状态中可显示“平台解析器可用/不可用”。

## 错误处理

助手把解析器错误转换成稳定的内部错误码和中文提示，不向扩展暴露原始命令输出：

- 需要登录：当前视频需要账号登录，v0.2.0 暂不支持。
- 会员或付费限制：内容受访问限制，不能下载。
- 地区限制：当前网络所在地区不可访问。
- 目标画质不可用：自动回退并在任务中说明实际选择。
- 解析器缺失、损坏或过期：提示安装包异常或升级 WebVideoHarbor。
- FFmpeg 不可用：沿用现有安装与修复提示。
- 网络中断：任务失败并允许重试。
- 平台临时限制：提示稍后再试。

日志不得记录 Cookie、完整签名媒体 URL、配对密钥或原始解析器输出。必要诊断只保留归类后的错误码、平台、任务阶段与解析器版本。

## 打包与供应链

- 打包脚本下载或接收固定版本的官方 `yt-dlp_macos` 通用可执行文件。
- 版本号和 SHA-256 写入受版本控制的依赖清单。
- 构建时必须核对 SHA-256、可执行权限和 macOS 架构。
- 发布包包含第三方许可或声明，并更新 `THIRD_PARTY_NOTICES.md`。
- 发布包不包含测试、缓存、日志、任务临时文件、配置或配对密钥。
- 助手启动时只检查内置解析器状态，不访问更新服务器。

## 测试策略

### 扩展自动测试

- 识别支持的 YouTube、Shorts、`youtu.be` 与哔哩哔哩单视频 URL。
- 拒绝非视频页、播放列表页和相似域名。
- 校验画质选择、任务请求与中文提示。
- 回归普通 MP4 与 M3U8 流程。

### 助手单元测试

- URL 标准化、平台识别与拒绝规则。
- 三种画质到固定格式选择器的映射与回退策略。
- 参数数组、禁用配置、无 Cookie、单视频与输出模板约束。
- 进度解析、阶段切换与安全错误分类。
- 取消进程树、重试和临时文件清理。
- 输出目录约束、文件类型验证与不覆盖发布。

### 集成测试

使用模拟 `yt-dlp` 可执行文件进行确定性集成测试，覆盖：

- 成功下载与合并结果发布；
- 进度更新；
- 登录、地区、网络与解析器错误；
- 取消时子进程和临时文件清理；
- API、扩展弹窗与任务状态联动。

### 打包测试

- 校验固定版本、SHA-256、可执行权限和 arm64/x86_64 兼容性。
- 解包后验证助手健康状态能发现内置解析器。
- 扫描并拒绝敏感状态和不应发布的测试源文件。

### 真实网站验收

- 用户提供的 YouTube 页面可生成有画面、有声音的文件。
- 用户提供的哔哩哔哩页面可生成有画面、有声音的文件。
- 最佳画质、1080P、720P 和回退规则正确。
- 普通 MP4 与非加密 M3U8 回归通过。
- 进度、取消、重试和 Finder 定位正常。

真实网站验收与确定性自动测试分开报告，以区分项目回归和平台临时变化。

## 非目标

v0.2.0 不包含：

- 登录态、Cookie 导入或账号密码；
- 会员、付费、私有、年龄限制或地区绕过；
- DRM 或加密绕过；
- 播放列表、频道、合集、番剧整季和批量下载；
- 字幕、封面、弹幕、音频提取或格式转换设置；
- 自动更新 `yt-dlp`；
- Windows 或 Linux 安装包。
