# WebVideoHarbor v0.2.1 公司网络兼容设计

日期：2026-07-27

## 背景与根因

v0.2.0 已能识别并提交 YouTube 视频，但用户所在公司网络会重置本地助手发出的 YouTube TLS 连接。诊断确认 DNS、普通 HTTPS、FFmpeg、解析器版本和配对均正常；同一 Google IP 使用 Google 域名可以建立 HTTPS，使用 YouTube 域名时在 TLS 握手收到服务器证书前被重置。

包内 `yt-dlp 2026.07.04` 已包含 `curl_cffi` 和 Chrome 网络特征模拟能力。只增加 Chrome 模拟后，部分 YouTube 请求可以越过连接重置，但当前公司共享出口仍可能收到 YouTube 的“确认不是机器人”响应。包内解析器还没有可用的 JavaScript 运行环境，而新版 YouTube 完整解析需要 JavaScript 挑战求解能力。

因此 v0.2.1 的目标不是绕过 YouTube 风控，而是让本地助手使用受控的浏览器兼容网络栈、补齐 JavaScript 运行环境，并准确区分网络过滤和平台验证。

## 已确认的产品边界

- 不读取、导出或保存 Chrome Cookie、账号、密码、浏览历史或登录信息。
- 不请求用户关闭 TLS 校验，不接受任意请求头、任意代理参数或任意 `yt-dlp` 参数。
- 不绕过登录、会员、付费、私有、年龄、地区、DRM 或 YouTube 机器人验证。
- 继续支持公开的 YouTube 与哔哩哔哩单视频，以及现有 MP4 和非加密 M3U8/HLS。
- YouTube 风控仍要求验证时，任务明确失败并给出可理解提示，不宣称能够保证下载所有公开页面。
- Bilibili、普通 MP4 和 M3U8 不进入 YouTube 专用兼容回退。

## 方案比较

### 采用：本地受控兼容回退

保留当前默认下载路径；只有 YouTube 任务在出现明确的 TLS 连接重置后，才清理第一次尝试的私有临时目录，并以固定 Chrome/macOS 网络特征重新执行。兼容尝试仍使用固定内置解析器、固定格式选择器、固定输出目录和最小环境。

优点是无需读取浏览器数据，改动集中在本地助手，且可通过模拟解析器进行确定性测试。缺点是只能解决网络传输层差异，无法消除 YouTube 根据共享出口 IP 触发的验证。

### 不采用：导入浏览器 Cookie

这是 yt-dlp 对部分 YouTube 验证问题的常见建议，但会扩大扩展权限和本地敏感数据处理范围，还可能给用户账号带来限流或封禁风险，与 WebVideoHarbor 的本地隐私边界冲突。

### 不采用：由 Chrome 转发或直接下载媒体

浏览器扩展可以尝试读取页面播放器状态并转发签名媒体地址，但 YouTube 页面结构变化频繁，音视频分离、分片下载、Service Worker 生命周期和大文件传输都会显著增加复杂度。媒体 CDN 仍可能受到公司网络过滤，不能可靠解决根因。

## 运行架构

### YouTube 两阶段执行

1. 助手按 v0.2.0 固定参数启动默认尝试。
2. 运行器保留有界、脱敏的诊断尾部，并判断失败是否属于明确的连接重置。
3. 只有命中允许回退的网络特征，才彻底清理第一次尝试的私有 staging 和子进程，再开始一次兼容尝试。
4. 兼容尝试固定增加 `--impersonate Chrome-136:Macos-15`，不从扩展、配置文件或环境变量接收目标值。
5. 兼容尝试成功后沿用现有文件验证、预留路径和原子发布流程。
6. 兼容尝试失败后按最终诊断归类，不再继续第三次策略切换。

以下错误不得触发兼容回退：需要登录或验证、访问限制、地区限制、解析规则变化、FFmpeg 缺失、输出错误、取消和进程安全错误。

### JavaScript 运行环境

macOS 包内置固定版本的 Deno，使用官方推荐的受限执行模式为 yt-dlp EJS 求解器提供运行环境。由于 macOS 的 arm64 与 x86_64 产物不同，打包目录保存两个经过哈希验证的官方二进制，助手只选择与当前进程架构匹配的文件。

兼容和默认尝试均以固定参数指定 `--js-runtimes deno:<validated-path>`。不启用远程组件下载；EJS 继续使用官方 `yt-dlp_macos` 已内置的匹配版本。助手启动时验证 Deno 的路径、普通文件类型、权限、架构和固定快照，运行时再次验证，防止被替换。

Deno 路径不会加入通用 `PATH`，也不会暴露给扩展或健康接口。健康接口只报告 JavaScript 运行环境是否可用及公开版本号。

### 安全边界

- 保留 `--ignore-config`、`--no-plugin-dirs` 和最小环境。
- 不继承代理、Home 目录或用户 `yt-dlp` 配置。
- 不经过 Shell，所有参数继续使用固定数组。
- Chrome 模拟目标和 Deno 路径均由助手构造，任务请求不能覆盖。
- 每次尝试使用独立私有临时目录；失败尝试的文件不会被下一次尝试复用。
- stderr 只保留现有大小上限内的内存诊断，用于分类，不写入持久日志或 API。
- 不记录完整媒体 URL、签名参数、配对密钥或原始平台响应。

## 错误模型与界面

新增或细分稳定错误语义：

- `network_filtered`：普通和兼容连接都被公司网络或安全设备重置。提示“当前网络阻止了本地下载连接，请联系网络管理员或更换网络”。
- `verification_required`：已经连接到 YouTube，但平台要求登录或确认不是机器人。提示“ YouTube 要求浏览器验证；为保护账号隐私，网页视频港不会读取登录信息”。
- `javascript_runtime`：Deno 缺失、损坏、架构不匹配或无法启动。提示“视频解析组件不完整，请重新安装网页视频港”。
- `extractor_outdated`：JavaScript 运行环境存在，但平台规则或 EJS 求解失败。继续提示升级应用。

任务响应和扩展弹窗只展示固定中文消息。健康状态增加“JavaScript 解析环境：可用/不可用”，不展示本机路径。普通临时网络故障继续使用现有 `network` 错误。

## 配置与兼容性

v0.2.1 不增加代理设置页，也不修改配对流程。运行策略属于助手内置行为，用户无需理解代理、TLS、IPv4 或命令参数。

现有 v0.2.0 请求和任务状态保持向后兼容。扩展与助手版本更新为 `0.2.1`；旧扩展连接新助手或新扩展连接旧助手时，继续通过现有健康检查给出版本/能力提示，不发送新型任意参数。

## 打包与供应链

- 依赖清单固定 Deno 版本、两个 macOS 架构下载地址、SHA-256 和许可信息。
- 获取脚本只接受预期普通文件，下载到私有临时文件后校验哈希，再以 no-clobber 方式放入缓存。
- 打包脚本验证 `yt-dlp`、Deno 和 FFmpeg 的文件类型、权限与架构。
- ZIP 不包含缓存、测试数据、日志、配置、密钥或临时下载文件。
- `THIRD_PARTY_NOTICES.md` 和安装说明补充 Deno/EJS 说明及网络兼容边界。

## 测试策略

### 运行器单元测试

- 默认尝试参数保持安全边界并包含固定 Deno 路径。
- 只有 YouTube 的明确连接重置触发一次 Chrome 兼容回退。
- 登录、地区、访问限制、输出、取消和普通解析错误不回退。
- 两次尝试使用不同 staging，第一次文件被完整清理。
- 兼容尝试参数固定，扩展请求不能注入目标或路径。
- 错误优先级正确：连接通过后出现验证时报告验证，而不是网络失败。
- Deno 缺失、替换、权限或架构异常均安全失败。

### 集成与回归测试

- 模拟默认连接重置、兼容模式成功并发布文件。
- 模拟两种连接均重置并返回 `network_filtered`。
- 模拟兼容连接后 YouTube 要求验证并返回 `verification_required`。
- Bilibili 平台任务只执行一次，不增加 YouTube 参数。
- MP4、M3U8、进度、取消、重试、Finder 定位和安全输出全部回归。

### 打包与真实验收

- 验证 arm64 和 x86_64 包均选择正确 Deno，且健康状态报告可用。
- 解包后在没有系统 Deno、Node、Cookie 和用户配置的环境运行模拟解析测试。
- 使用用户提供的 YouTube 页面验证公司网络兼容模式；若 YouTube 返回验证，确认提示准确且没有读取浏览器数据。
- 使用用户提供的 Bilibili 页面以及公开 MP4/M3U8 页面回归。

## 成功标准

- 当前公司网络中的 YouTube TLS 重置能够自动进入受控 Chrome 兼容路径。
- 应用具备新版 YouTube 所需的本地 JavaScript 求解环境。
- 不读取浏览器登录信息，不降低 TLS 安全性，不开放任意运行参数。
- 可下载时生成有画面、有声音的安全文件；平台要求验证时给出准确、可行动且不误导的说明。
- v0.2.0 的 Bilibili、MP4、M3U8 与安全输出行为无回归。
