# WebVideoHarbor v1.0.0 Community Edition 设计

**日期：** 2026-07-28

**状态：** 已确认

**取代：** `2026-07-27-webvideoharbor-commercialization-design.md` 与 `2026-07-27-webvideoharbor-v0.3-commercial-editions.md` 中的商业化方向

## 背景

WebVideoHarbor 当前公开版本为 v0.2.1，由 Chrome 扩展和 macOS 本地助手组成。它支持普通 HTTP(S) 视频、非加密 M3U8/HLS，以及无需登录即可观看的 YouTube、Bilibili 公开单视频；微信视频号仅在浏览器实际暴露普通 MP4 或非加密 M3U8 时做最佳努力识别。

项目曾规划免费版、Pro 永久版、远程安装服务与离线激活。该商业化方向现已取消。项目的新目标是完全免费、完整开源、只用于技术学习交流，不销售软件、不设置功能付费墙，也不建设支付、账号或在线授权服务。

免费开源和学习目的不能自动排除平台条款、版权投诉或分发平台下架风险。因此新版保留受限的平台兼容能力，但不把特定平台下载作为宣传卖点，并要求用户主动确认使用边界后开启。

## 产品定位

新版名称为 **WebVideoHarbor v1.0.0 Community Edition**。

对外定位：

> WebVideoHarbor 是一个完全免费、开源、本地运行的网页媒体技术工具，用于学习网页媒体识别、浏览器与本地助手通信、流媒体分片处理和 FFmpeg 合并。

项目 README、Release 标题、截图和介绍以通用网页媒体技术能力为主，不使用“YouTube 下载器”“Bilibili 下载器”“视频号下载神器”“全网视频下载”“破解”或“绕过限制”等宣传口径。平台名称只在兼容性说明、使用边界、第三方依赖和故障排查中如实出现。

## 目标

- 软件及全部第一方源代码免费公开。
- 使用 MIT 许可证发布第一方代码。
- 普通 MP4、WebM 和非加密 M3U8/HLS 保持默认可用。
- YouTube、Bilibili 等实验性平台兼容能力随完整安装包提供，但默认关闭。
- 用户阅读并确认版权与平台边界后才能主动开启实验性平台兼容。
- 开关由扩展和本地助手共同执行，不能仅通过隐藏界面实现。
- 所有媒体处理和设置继续保留在用户电脑本地。
- 只通过 GitHub 发布源码和 macOS 安装包，Chrome 扩展由用户手动加载。
- 保留明确的第三方软件来源、版本和许可证说明。

## 非目标

- 不开发免费版、Pro 版、激活码、付费功能或支付系统。
- 不申请 Chrome Web Store 上架。
- 不读取浏览器 Cookie、账号凭证或登录状态。
- 不支持会员、付费、私有、年龄限制、地区解锁或其他受控内容。
- 不破解加密 M3U8、DRM 或复制保护。
- 不规避平台登录、机器人验证、访问控制、风控或限流。
- 不允许用户传入任意 yt-dlp 参数、请求头、代理或可执行文件路径。
- 不承诺第三方平台长期兼容，也不宣传成功率。
- 不增加服务器、账号、遥测、崩溃上报或远程开关。

## 功能分层

### 默认通用功能

以下功能不需要额外确认：

- 识别和下载普通 HTTP(S) MP4、WebM 等直接媒体资源；
- 识别、检查、下载并合并非加密、非 DRM 的 M3U8/HLS；
- 下载进度、取消、重试、文件安全命名和 Finder 定位；
- Chrome 扩展与配对后的本地助手通信；
- 本地 FFmpeg 检查和受控调用。

### 实验性平台兼容

完整 macOS 安装包继续包含固定版本的 yt-dlp 和 Deno，以及相应第三方许可证。平台兼容只处理现有严格允许列表中的公开单视频 URL，继续保持不读取 Cookie、不接受任意参数和不处理受限内容的边界。

平台兼容默认关闭。关闭时：

- 扩展不为已知平台页面生成平台下载卡片；
- 本地助手拒绝平台 URL 下载任务；
- 普通媒体扫描和下载保持正常；
- 微信视频号等页面即使暴露普通媒体，也按实验性平台边界处理，避免关闭状态下通过通用扫描绕过设置。

## 用户开启流程

扩展设置页增加“实验性平台兼容”开关，初始为关闭。

用户首次尝试开启时显示以下核心提示：

> 此兼容功能仅用于技术研究，以及处理您拥有版权、已获授权或平台明确允许下载的内容。请勿用于会员、付费、私有、加密、DRM 内容，也不要规避登录、地区或访问限制。

用户必须明确点击“我已了解并继续”。关闭弹窗、取消或未完成确认时保持关闭。

确认后：

1. 扩展通过已经配对和鉴权的本地 API 更新助手设置；
2. 助手成功持久化设置后，扩展才把本地显示状态更新为已开启；
3. 扩展重新扫描当前页面，允许显示受支持的平台卡片；
4. 用户可随时关闭，关闭成功后平台任务立即被助手拒绝。

如果扩展状态与助手状态不一致，以助手返回的实际状态为准。用户更换助手数据目录、清除状态或安装新版时，不应凭扩展中的旧值静默重新开启。

## 本地设置与 API

本地助手在现有应用状态目录保存版本化设置，例如：

- `experimentalPlatformCompatibilityEnabled`：布尔值，默认 `false`；
- `platformNoticeVersion`：用户最近确认的提示版本；
- `updatedAt`：用于故障排查的本地更新时间，不上传。

设置文件必须使用现有状态目录安全边界、限制权限、原子写入，并拒绝符号链接或异常文件类型。损坏或无法解析时回退为关闭状态，不能因错误而自动开启。

配对后的本地 API 增加：

- 读取当前兼容设置；
- 在携带当前提示版本和明确确认字段时开启；
- 关闭兼容设置。

所有平台任务在进入解析器之前再次读取助手侧状态。未开启时返回稳定错误类型，扩展展示“实验性平台兼容尚未开启”，不启动 yt-dlp、Deno 或 FFmpeg。

## 错误处理

- 设置保存失败：扩展保持旧状态并提示“设置未保存，请确认本地助手正在运行”。
- 助手设置损坏：安全回退为关闭并给出可恢复提示。
- 解析器不可用：只影响实验性平台兼容，普通 MP4/M3U8 继续工作。
- 平台要求登录、Cookie、会员、验证或 DRM：停止任务并给出对应边界提示，不建议规避方法。
- 平台规则变化：提示兼容暂不可用，不自动下载或执行不受控更新。
- 用户关闭兼容功能时已有平台任务：允许用户选择取消；默认不新建后续平台任务。实现计划需明确现有任务的确定性处理并覆盖测试。

## 隐私与安全

- 不新增网络服务或远程控制面。
- 不收集浏览历史、媒体 URL、下载记录、平台选择或确认状态。
- 不记录签名媒体 URL、页面完整查询参数、配对密钥或解析器原始输出。
- 不把设置或下载任务发送给项目维护者。
- 本地 API 继续要求配对令牌、来源限制、请求大小限制和严格数据校验。
- 平台 URL 继续使用严格域名和页面类型允许列表，禁止把助手变成通用 yt-dlp 远程执行入口。

## 开源和第三方许可证

仓库根目录新增标准 MIT `LICENSE`，版权声明使用项目所有者确认的名称和年份。README 增加许可证摘要。

MIT 只适用于 WebVideoHarbor 第一方代码。安装包内的 yt-dlp、Deno 及其他第三方组件继续分别遵守其自身许可证。`THIRD_PARTY_NOTICES.md`、版本固定文件和安装包内许可证不得因加入 MIT 而删除。

发布前必须再次核对所分发 yt-dlp 独立可执行文件的完整许可证清单及对应源码获取说明。MIT 许可证不能替代第三方 GPL 或其他组件的义务。

## 文档与宣传边界

README 首页包含：

- 完全免费、开源、本地运行的技术项目定位；
- 通用 MP4、WebM、非加密 M3U8/HLS 能力；
- 无账号、无遥测、无上传；
- 只处理自有、已授权或明确允许下载的媒体；
- GitHub 手动安装入口。

兼容性与使用边界章节如实说明实验性平台模块、默认关闭、依赖、局限和禁止场景。不能为了弱化宣传而隐瞒实际功能或第三方组件。

旧商业化文档保留在 Git 历史中，但当前 README 和开发计划必须明确说明其已被本设计取代，不再实施激活、Pro 或付费服务。

## 测试策略

### 扩展测试

- 首次安装和缺少设置时默认关闭；
- 关闭状态不生成平台卡片；
- 普通 MP4、WebM、M3U8 候选不受影响；
- 首次开启必须展示当前版本提示并获得明确确认；
- 取消提示不会开启；
- 助手保存成功后才显示开启；
- 关闭后立即停止平台识别；
- 助手状态与扩展缓存不一致时以助手为准；
- 不增加 Cookie 权限或平台账号相关权限。

### 助手测试

- 设置不存在、损坏或版本未知时默认关闭；
- 设置文件安全创建、原子更新、权限和异常文件拒绝；
- 未开启时平台 API 在启动解析器前被拒绝；
- 明确确认且提示版本匹配时才能开启；
- 关闭操作可重复并立即生效；
- 普通 MP4/M3U8 任务不受平台开关影响；
- 现有 URL 规范化、单视频、安全临时目录和无 Cookie 边界继续通过。

### 打包和文档测试

- 版本统一为 `1.0.0`；
- 完整安装包包含扩展、助手、固定解析器、Deno 和全部许可证；
- 包内平台设置初始为关闭；
- 不包含激活公钥、发码工具、Pro 文案或支付入口；
- MIT `LICENSE`、第三方通知、安装说明和使用边界存在且一致；
- macOS arm64 与 x86_64 架构和哈希验证继续通过。

### 本机验收

- 普通 MP4 和非加密 M3U8 在默认状态可完成下载；
- YouTube、Bilibili 在默认状态不启动平台解析；
- 确认开启后，符合现有边界的公开单视频进入既有受控下载流程；
- 再次关闭后平台任务被拒绝；
- 登录、验证、会员、付费或 DRM 内容仍然失败且提示准确。

## 发布与迁移

发布顺序固定如下：

1. 完成功能、文档、许可证和自动测试；
2. 构建并在本机验证 v1.0.0 Community Edition；
3. 提交并推送源码；
4. 创建 `v1.0.0` 标签和 GitHub Release；
5. 从 GitHub 重新下载发布资产，验证安装包、版本、哈希和基本功能；
6. 新版确认可用后，删除旧 `v0.2.1` GitHub Release；
7. 删除远程 `v0.2.1` 标签；
8. 保留所有历史提交，不改写 Git 历史。

删除旧 Release 和远程标签属于外部破坏性操作，只能在新版已验证且用户已明确授权的阶段执行。删除不能追回他人已下载、克隆、分叉或缓存的副本。

## 成功标准

- 仓库和安装包不含任何商业版、激活或收费机制。
- 第一方代码具有明确的 MIT 许可证。
- 默认安装后平台兼容确实关闭，并由扩展与助手双重执行。
- 用户明确确认后仍能使用现有受限平台兼容能力。
- 普通 MP4、WebM、非加密 M3U8/HLS 不发生功能回退。
- 文档宣传中立、功能披露准确、边界清楚。
- 无 Cookie、登录、会员、付费、DRM 或规避能力。
- v1.0.0 Release 可下载、可安装、可验证后，旧 v0.2.1 Release 和远程标签按确认方案删除。
